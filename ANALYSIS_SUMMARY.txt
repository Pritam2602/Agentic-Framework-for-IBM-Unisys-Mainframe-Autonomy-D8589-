6-STAGE AGENT PIPELINE:

  User Query (string)
        ↓
  [1] INTENT AGENT (WHAT)
      Understand user intent using NLP
      Output: entities, task, filters, confidence
      Pattern: LLM + Rule-based fallback
        ↓
  [2] CONTEXT RESOLUTION (WHERE)
      Map entities to data sources
      Output: IBM programs/datasets, Unisys APIs
      Pattern: Metadata-based discovery
        ↓
  [3] PLANNER (HOW)
      Create execution plan with dependencies
      Output: DAG with steps, risk levels, safety guards
      Pattern: Deterministic with optional LLM refinement
        ↓
  [4] EXECUTION (RUN)
      Execute plan through appropriate systems
      Output: Raw data from IBM and Unisys
      Pattern: Multi-system routing, safe_mock mode
        ↓
  [5] NORMALIZATION (CANONICAL)
      Map to common schema, enforce authority rules
      Output: Normalized records
      Pattern: Field alignment, data quality checks
        ↓
  [6] FEDERATION INTELLIGENCE
      Discover relationships, recommend views
      Output: Federated view with confidence
      Pattern: Entity graph building, join key resolution
        ↓
  Federated View Result


CRITICAL RULES IDENTIFIED:

  ⚠️  FINANCIAL INTEGRITY
      • IBM CardDemo = FINANCIAL AUTHORITY
      • Unisys ePortal = BEHAVIORAL ENRICHMENT
      • NEVER add amounts together
      • Monitor at normalization stage
      • Violations = CRITICAL ALERT

  ⚠️  CROSS-SYSTEM FEDERATION
      • customerId must match exactly (join key)
      • Join failures = data inconsistency
      • Target match rate > 99%
      • Mismatches = CRITICAL ALERT

  ⚠️  LLM RELIABILITY
      • Each stage has LLM + fallback
      • Fallback activates if LLM fails
      • Target fallback rate < 5%
      • Token usage tracked for cost
