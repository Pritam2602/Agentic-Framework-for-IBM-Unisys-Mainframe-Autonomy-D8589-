WHAT THIS MEANS:
  JCL defines HOW and WHEN COBOL programs run on the mainframe.
  Each JCL job is a batch execution unit - it runs one or more steps in sequence.

  Key patterns in this application:
  - IDCAMS jobs (ACCTFILE, CARDFILE, CUSTFILE, XREFFILE, etc.) manage VSAM datasets:
    they DELETE old clusters, DEFINE new ones, and REPRO (copy) data into them.
    These are the "database setup" jobs.

  - Business processing jobs run COBOL programs:
    POSTTRAN  -> CBTRN02C  (post daily transactions)
    INTCALC   -> CBACT04C  (calculate interest)
    CREASTMT  -> CBSTM03A  (generate customer statements)
    READACCT  -> CBACT01C  (extract account data)
    CBEXPORT  -> CBEXPORT  (export all data)

  - Utility jobs use system programs:
    SORT      -> sort/merge transaction files
    IEFBR14   -> dummy program for dataset allocation/deletion
    SDSF      -> open/close files in CICS

  - Compile jobs (BATCMP, CICCMP, etc.) use PROCs to compile COBOL source.

  - The COND parameter controls step execution:
    COND=(0,NE) means "skip this step if any prior step returned RC != 0"
    This creates a pipeline where later steps only run if earlier ones succeeded.
